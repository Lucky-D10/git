# 屏幕比例与准备状态

## 屏幕如何显示

全局布局由 `web/static/js/layout.js` 和 `web/static/layout.css` 管理。横屏使用 800×480 逻辑画布，字号、按钮、插画、仪表与曲线等比例变化，而不是只把卡片横向拉宽。

| 浏览器可用区域 | 应用区域 | 留白 |
| --- | --- | --- |
| 800×480 | 800×480 | 原生铺满，适合目标树莓派屏幕 |
| 1024×600 | 1000×600 | 左右各 12px |
| 1280×800 | 1232×739.2 | 水平居中，上下约 30px |
| 1920×1080 | 1440×864 | 居中，避免在大屏上无限放大 |
| 小于 700px 宽 | 按手机宽度重排 | 允许纵向滚动 |

长报告、历史及展开的维护内容继续纵向滚动。主体验页面以完整显示主要操作为目标。浏览器工具栏和系统缩放会改变可用区域；这些测试是浏览器视口验证，不代表已完成树莓派硬件验收。

使用 `transform` 保持 ECharts 指针坐标与画布坐标一致，并在放大比例变化时重新配置画布像素密度。普通数据推送复用图表，不逐帧重建。全程回顾是一张主图：浅线为原始值、深线为平滑值、虚线为个人目标。图下是时间范围滑块，已取消容易误认为第二张曲线图的缩略数据背景。

## 准备页是真实状态的视图

后台每路独立保存 `connected`、`worn`、`calibration`、`calibration_progress`、`valid` 和 `reason`。前端 `device-state.js` 根据实时快照呈现主要提示，不用固定倒计时模拟准备过程。

| 事实 / 原因 | 主要提示 |
| --- | --- |
| 后台实时连接过期 | 状态连接中断，所有检查等待更新 |
| 未连接 | 头环未连接 |
| 已连接但明确未佩戴 | 已连接 · 未佩戴 |
| 设备处于 baseline | 基线采集中 |
| 基线超时 | 基线采集超时 |
| 校准完成但缺少有效新样本 | 等待有效新信号 |
| 有效新样本通过后台检查 | 准备好了 |

佩戴未知时显示“设备未单独提供”，不会显示已确认。进度只使用设备上报值；未提供百分比时使用不定进度提示。设备基线与个人目标是两回事。双人分别显示事实，未完成准备的一路不会被另一条已就绪车道覆盖。

后台仍决定开始是否合法。状态帧携带基线信息、触发校准超时，但不会增加样本数或刷新真实采样时间。`EngineTests.test_status_only_baseline_updates_do_not_create_fresh_samples` 覆盖此边界。后台代码修改在下次服务启动时加载；网页样式刷新即可生效。

## 全局图形规范

- 头像徽标使用玩家已保存的图案，选人、准备、训练及成果保持一致；长昵称省略显示，不挤压按钮。
- 蓝橙人物使用同一套本地 SVG 插画，补充衣物与面部层次；未佩戴时不显示已戴头环的姿态，准备状态配合文字和状态徽标。
- 车辆继续使用本地蓝橙素材；控制、准备卡片、训练卡片、报告与维护共用字号、圆角和留白规范。
