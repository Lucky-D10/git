# 持续测试过程记录

2026-09-28：第二次 60 秒测量过程中，Playwright APIRequestContext 的健康探针发生一次 socket hang up。该次运行按失败处理，未生成通过结果。随后独立读取 /api/health 返回 ready=true，后台进程仍在运行，服务日志没有异常；WebSocket 在测试退出时断开。

探针每 5 秒查询一次，与 Uvicorn 默认空闲 keep-alive 超时重合，怀疑存在复用过期连接的竞态。初次调整仅发送 Connection: close，仍出现 ECONNRESET；该请求头并不能保证客户端不先复用已有连接。因此改用 Node HTTP 的 agent:false，确保每个健康探针新建 TCP 连接，不重试或吞掉失败。此为测试工具调整，并未放宽 ready、JavaScript 异常或图表实例数断言，连接竞态仍是推断。

紧接着的一次重跑在“新一场”按钮等待超时：前次失败退出浏览器后，后台正确将未完成训练保留为暂停态，因此不能直接覆盖会话。测试脚本已补上显式结束并确认保存，再创建下一场的步骤；产品没有放宽覆盖未结束会话的限制。

随后一轮完成了 60 秒采样和保存，但图表实例断言错误地固定要求总数为 1。脚本为了结束上次暂停会话已进入报告页，页面因此正常保留两个报告图表实例。断言改为“所有持续采样的实例数等于第一条采样”，用来检测运行期间是否增长。完整采样文件现在在断言之前写入，失败数据也可检查，不将先前的失败轮次改称通过。

使用独立 TCP 探针后的完整 60 秒测量通过，12 次健康检查正常，490 个显示确认的 p95 约为 141 ms，图表实例稳定为 3。原始结果另存 `reports/stage3/soak-60-seconds.json`。随后补充状态记录，将图表数量比较限定为进行中阶段，避免 7200 秒到达时自动进入报告页、正常创建报告图表被误报；同时禁止将意外暂停/中断判为通过。完整浏览器流程再次通过，无外域请求、页面异常或横向溢出。
