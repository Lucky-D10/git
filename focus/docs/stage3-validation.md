# 第三阶段验证记录

验证日期：2026-09-28。环境为 Windows、Python 3.9.13、项目 `.venv`、Edge 无头浏览器，窗口 800×480；所有动力验证使用显式选择的 simulation 模式。完整依赖见 [环境记录](environment-stage3.json) 和 [开发环境版本](development-web-lock.txt)。树莓派未连接，本记录不代表硬件验收通过。

## 已完成的验证

| 范围 | 结果与证据 |
| --- | --- |
| 自动测试 | `.venv/Scripts/python -m unittest discover -q`：90 项全部通过，没有依赖缺失跳过。包含真实控制线程、临时 SQLite、HTTP/WebSocket、状态转换、回放、去重、绑定与存储异常。测试输出中的 `disk full` 是故障注入场景。 |
| 浏览器完整流程 | `tools/test_web_browser.cjs`：准备、开始、暂停、继续、结束、报告、导出、历史、维护和双人虚拟竞速。还检查表单不会被快照覆盖、第二页面不能领取已占用权限、断开后暂停、刷新不创建新场。结果保存于 `reports/stage3/browser-result.json`。 |
| 本地页面资源 | 浏览器测试阻止并记录外域请求，结果为零外域请求、零页面 JavaScript 异常；加载的是本地官方 ECharts 5.6.0。不是仅检查 HTML 中没有 CDN 地址。 |
| 屏幕布局 | 800×480 截图保存在 `reports/stage3/*-800x480.png`；训练页关键读数、曲线和暂停/结束/急停按钮可见，无横向溢出。实际触摸手感待实机测试。 |
| 60 秒持续短测 | 12 次独立 TCP 健康探针全部正常，训练期间图表实例数始终为 3（本轮先结束遗留暂停会话，两个报告图表已创建）。完整采样保存在 `reports/stage3/soak-60-seconds.json`，`soak-result.json` 为脚本最近一轮结果。 |
| 显示确认耗时 | 本轮隔离时间窗内 490 个首次显示的真实新样本，p95 约 141 ms。指标从适配器接收数据，到浏览器帧更新后确认返回后台，含返程耗时；不含头环采样/传输固有延迟，也不是物理屏幕像素测量。 |
| 启动等待页面 | 自动测试覆盖后台未就绪时显示等待、就绪后跳转；Windows 上未执行 systemd、labwc 或 shell 部署脚本。 |

短测第一/末次堆内存分别约 16.6/29.9 MB，DOM 节点数 5544/1423。堆内存受分配与 GC 时点影响，60 秒数据不足以判断是否存在长期增长；通过标志只表示脚本的健康、状态、资源与图表断言通过，不代表两小时内存验收。

补充运行状态采样和自动结束边界处理后，再运行 10 秒复核：两次采样均为进行中，图表实例稳定为 1，健康检查正常，85 个显示确认的 p95 为 125 ms。此结果存于 `reports/stage3/soak-result.json`，没有覆盖上述 60 秒归档。Python 编译、Node 脚本语法检查与 `git diff --check` 通过。

前几轮测试工具失败以及修正过程保留于 [持续测试过程记录](stage3-test-notes.md)。最终健康探针使用 `agent:false` 新建连接，未重试、忽略或改写失败轮次。持续测试脚本也会将后续异常和已采样数据保存为 `soak-failure-*.json`。

## 目标树莓派仍需验收

- 按 [部署说明](stage3-web.md) 安装服务、设置专用账户及设备权限，记录 Pi 型号、系统、SDK、GPIO 和 Python 版本。
- 连续 20 次真实冷启动进入可操作页面；每次人工确认后运行 `tools/record_pi_boot.py --ui-confirmed`。不同 Linux boot_id 只用于防重复，实际断电冷启动仍由现场执行。
- 断开外网，完整完成训练、保存、查询历史和基础报告。
- 连续 2 小时运行 `tools/soak_web.cjs`，分析预热后的内存、GC 和响应趋势。脚本默认 7200 秒，仅允许模拟模式；实机采集稳定性另行测量。
- 实测有效样本接收至显示的 p95，以 300 ms 为调优目标；分别记录头环自身延迟与页面耗时。
- 实测 GPIO、进程失效、掉电和保护硬件撤销动力；服务自动重启不能代替实体安全保护。

`reports/` 是本地运行产物目录，不纳入源码版本控制。需留档时将结果 JSON、截图和现场环境记录一起保存。
