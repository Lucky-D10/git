# 访客体验、单次分析与 DeepSeek 接入（前三阶段）

## 已实现范围

1. 默认访客模式：每位访客本次到访使用独立 visit_id，每轮使用独立 participant_id；头环、蓝橙位置不作为个人身份。
2. 单次分析：完整记录驱动质量检查、时间加权平均、时间加权中位数/四分位距、标准差、达标片段、最长连续达标、前中后三段与缺测原因；本地规则生成建议。
3. 异步 AI：DeepSeek Chat Completions JSON 模式，可配置模型；持久化任务、模板优先、有限重试、重启恢复、访问隔离和结果版本记录。

未实施第四阶段的群体运营仪表盘，也未建立长期个人档案关联、二维码分享、原始 EEG 采集或训练预测模型。旧档案管理保留在工作人员入口，但旧 local-1/local-2 记录标为身份未确认，不自动建立个人成长结论。

## 现场操作

- 首页选择活动和人数，默认每个位置是新访客，无需注册。
- 结束后，基础结果立即出现；“查看详细数据”包含“本次分析与建议”。
- “我再体验一轮”保留本次到访。确认页可选择上一轮蓝色/橙色访客，或替换其中一位为新访客；同一个人不能占两个位置。
- “换下一位 · 结束到访”关闭到访并清理页面。下一位使用新的身份；旧报告、历史和下载地址不再对当前访客开放。
- 双人报告包含两路信息，因此其中一位已经换人时，上一场完整双人报告不再向普通访客开放；保留访客的单路同条件统计仍可用于新报告比较。
- 默认历史页仅显示当前到访有权查看的记录；“全部记录”不合并计算个人趋势。
- 新一轮会话或结束到访都会使工作人员令牌失效。刷新页面也不会保存工作人员令牌。

## 数据与统计口径

数据库新增 visits、participant_identity、analysis_jobs、analysis_reports 四张表，保留原有表结构。建表幂等，可读取旧库；没有身份映射的旧记录仅工作人员可看。启动备份机制仍由原存储层负责。

分析任务和终态会话数据在同一个 SQLite 事务中提交。后台 worker 只读取已提交且 reports.status=ready 的记录，云端请求期间不持有数据库连接或事务。AI 结果独立存储，不会被基础报告再次写入覆盖；原 ai_json 字段也改为更新时保留。

分析按时间保持最近一个有效 Attention，最多保持至 data_timeout。暂停、设备失效、缺测断开连续达标；不插值、不将缺测当作零。前中后三段按实际运行时长划分，暂停不占分段时间。原页面基础统计保留原算法口径；新增分析标注“时间加权”，因采样间隔不等可与样本算术平均不同。

第一版分析资格规则：正常结束、有效时间至少 10 秒、覆盖率至少 80%、运行中至少两个有效样本。这是版本化产品门槛，不代表科学或临床可靠性标准。覆盖不足、短体验及中断仍显示基础事实和检查设备建议。

同次到访比较只选更早、同一 visit_id、合格且分析版本一致的上一轮。同条件摘要包含运行模式、人数、任务、目标、预设时长/距离、正式/体验模式、算法和有关采样控制参数。设备位置可以变化；不同目标不直接比较达标率。没有可靠关联不跨到访比较。

每份结果保存输入摘要哈希、特征版本、规则版本、提示词版本、provider/model 和数据来源。当前是按参与者单份缓存；新版本不会自动重算旧报告。若要重新处理旧记录，应另做经过审核的重算迁移。

## 默认运行：不需要密钥

```powershell
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python app.py web --mode simulation
```

FOCUS_AI_PROVIDER 默认 disabled，不产生任何模型请求。所有分析和建议均可本地完成，页面明确标识“本地分析”；模拟记录也显式标注来源。

## 启用 DeepSeek

设置服务进程的环境变量，之后重启应用。不要把真实密钥写进配置 JSON、页面或提交到 Git。

| 变量 | 含义 |
|---|---|
| FOCUS_AI_PROVIDER | 设置为 deepseek 启用；默认 disabled |
| FOCUS_AI_MODEL | 设置为账户中可调用的模型 ID；默认空，防止误调用 |
| DEEPSEEK_API_KEY | 服务端密钥，必填，不在聊天中发送 |
| FOCUS_AI_BASE_URL | 默认 https://api.deepseek.com；只接受 HTTPS，禁止 URL 中携带账号口令 |
| FOCUS_AI_TIMEOUT | 默认 15 秒，配置限制为 2～30 秒；连接最多 3 秒 |
| FOCUS_AI_ALLOW_SIMULATION | 默认 0；设为 1 才允许模拟记录发送到云端并产生费用 |
| FOCUS_STAFF_PIN | 至少六位的工作人员口令；未设置时历史解锁关闭 |

PowerShell 示例（先在本机安全设置 DEEPSEEK_API_KEY）：

```powershell
$env:FOCUS_AI_PROVIDER = 'deepseek'
$env:FOCUS_AI_MODEL = 'deepseek-flash'
$env:FOCUS_AI_ALLOW_SIMULATION = '1'
.venv/Scripts/python app.py web --mode simulation
```

示例模型 ID 来自 2026-10-05 检查的 [DeepSeek 官方首次调用文档](https://api-docs.deepseek.com/zh-cn/)，部署时核对账户支持情况。传输使用 /chat/completions、response_format=json_object、非流式与关闭思考模式；由本地校验结果结构，不把 JSON 模式当作事实正确性保证。[JSON 模式](https://api-docs.deepseek.com/guides/json_mode/)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。

服务商故障、限流、无效 JSON、输出截断、未知证据/建议和不支持的历史结论均使用模板回退。短记录和不合格记录不调用模型。每位参与者最多两次调用（含自动及手动重试）；不可用错误最多自动重试一次，其他输出错误可在页面手动重试，仍受总次数限制。

本地任务先于云端任务执行；最多八个待云端处理的任务，超过时本场保留模板。持久化队列不丢基础分析，旧到访的迟到结果写回原参与者，不切换到下一位页面。

只发送 scope、mode、本地事实、允许的建议、限制说明以及本地小目标、反馈方向和对应事实的数字占位符。不发送姓名、访客/参与者 ID、原始样本、原始脑电或其他玩家数据。每个请求独立，不共享对话历史。自动校验覆盖结构、证据编号、建议集合、数字占位符和部分不支持的表述，不能证明任意自然语言解释的语义完全正确；页面标注 AI 辅助解读，仍需要现场评价后扩大使用。

### 面向儿童和青少年的反馈（2026-10-06）

新报告按“本轮小结—下一轮的小目标—可以这样做—鼓励”展示。即使没有云端也保留针对本轮数据的小目标和方法；AI 使用较易理解的中文解释真实数值。

规则版本 guest-rules-v2、提示词版本 student-coaching-v2。有效数据不足时只建议准备好再体验，不设置成绩目标；合格记录按以下优先级选择反馈：达标率低于 30%、后段平均读数比前段低至少 8、四分位距至少 25 且出现至少三个达标片段、达标率至少 80%、其他合格记录。分段覆盖不足时不解释前后变化。上述阈值用于产品建议分支，不是能力分级或科学评价标准。

低达标率从最多五秒的小片段尝试；普通记录在本轮最长片段上增加一到两秒左右的可选目标；高达标率先尝试重复。不超过本轮运行时长，不自动改变门槛、设备参数或延长体验。目标不是必须达到的考核，也不承诺改善学习成绩。方法包括选一个任务提示、读数波动时继续眼前任务、后半段提醒自己回到任务，以及结束后和老师回顾感受。

AI 必须引用事实编号和相应的中文占位符，例如 `{连续达标}`；程序从本地统计填入数值，禁止模型自行改写数字、选择不存在的目标或建议。鼓励不以聪明、努力程度、排名或固定能力给孩子贴标签。

新版内容用于升级后新完成的体验。已有缓存报告不自动重写；旧版排队报告缺少新版输入时保留本地结果，不发送不兼容的云端请求。特征统计版本保持 guest-analysis-v1，所以本次到访同条件统计仍可比较。

Windows 下不自动加载 .env 文件，请设置启动进程环境。树莓派 systemd 服务可选读取 /etc/focus/ai.env，模板见 deploy/ai.env.example。真实文件置于仓库外，建议仅 root 可读写；systemd 可在降权前读取。停机等待增加至 45 秒以容纳有界云端任务；意外退出的 running 任务租约过期后恢复，仍受调用次数限制。

### 本机配置启动方式

可使用 `tools/start_deepseek.py` 加载仓库根目录下被 Git 忽略的 `.env.deepseek`，然后调用原来的 `app.py web` 入口。普通 `app.py` 启动仍不会自动读取该文件。此文件只保存本机配置，不随仓库分发；字段参考上表，不包含工作人员口令。请勿提交或分享真实文件。

```powershell
# 仅检查配置能否加载，不请求云端
.venv/Scripts/python tools/start_deepseek.py --check
# 模拟体验，默认仍使用本地报告
.venv/Scripts/python tools/start_deepseek.py --mode simulation
# 明确允许模拟数据调用 DeepSeek，会使用 API 额度
.venv/Scripts/python tools/start_deepseek.py --mode simulation --allow-simulation
# 在已配置头环的设备上启动实机模式
.venv/Scripts/python tools/start_deepseek.py --mode hardware
```

`--config`、`--web-port` 等 Web 启动参数会传给原入口。已有服务需停止后按上述方式重启，才会使用本机配置。

## 验证

```powershell
.venv/Scripts/python -m unittest discover -v
```

tests/test_guest_analysis.py 使用固定数据和模拟 HTTP 验证时间口径、身份隔离、双人换位、同条件比较、终态提交、缓存、云端失败和迟到结果。

浏览器验收使用隔离模拟数据库，设置 FOCUS_STAFF_PIN=guest-test-pin。运行 tools/test_guest_browser.cjs；默认服务地址为 http://127.0.0.1:8767，可用 FOCUS_URL 覆盖；支持 PLAYWRIGHT_MODULE、BROWSER_PATH 指定测试运行时。测试涵盖单人、续玩、换人、刷新、双人报告、口令和移动端截图。不要对现场正在使用的实例运行此测试。

2026-10-05 验证结果：全部 114 项 Python 测试通过；访客浏览器验收通过；原有浏览器回归通过，覆盖训练、双人竞速、暂停/恢复、刷新接管、导出、急停、复位、800×480 核心页面和手机宽度。两套浏览器检查均未记录页面 JavaScript 错误。测试产物位于忽略提交的 reports/guest-qa 和 reports/ui-v2。

2026-10-06 新版学生反馈验证：新增数据分支、目标上限、数字占位符、未知证据、行为推断和旧版排队报告兼容测试；访客浏览器验收覆盖小目标、步骤和鼓励。使用人工构造的模拟记录实际调用 DeepSeek 并通过结构校验，未发送真实访客记录。人工检查中发现并收紧了从读数推断行为的表述约束；少量样例不代表所有生成内容都可靠，现场仍应抽查。
