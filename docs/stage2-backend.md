# 阶段二后台契约与验收

本阶段把训练和竞速的判定、计时、统计与动力输出放到 `backend/`。Tk 页面只读取快照并提交带 `session_id` 的操作意图，因此页面卡顿不会改变后台计时，也不能让上一场的回调控制下一场。

## 状态和转换

后台同时维护设备、会话和安全三层状态。每路设备事实独立保存：连接、佩戴、校准进度、设备代次、最后一个真实样本的时间和数据原因。会话状态为 `preparing`、`countdown`、`running`、`paused`、`finished` 或 `aborted`；安全状态为 `inhibited`、`allowed`、`emergency_locked` 或 `fault_locked`。安全状态优先，除 `allowed` 外一律输出零动力。

| 意图/事件 | 前置条件 | 后台动作 | 页面反馈与失败记录 |
|---|---|---|---|
| `prepare` | 会话已结束或待机，安全为 `inhibited`，无记录故障 | 先校验新配置、结束旧会话、强制落盘，再创建新会话和配置快照 | 显示新会话；校验失败写 `invalid_prepare` |
| `start` | 所选玩家每路连接、佩戴、校准完成且数据新鲜 | 冻结规则和配置，进入统一倒计时 | 显示倒计时；条件不足写 `intent_rejected` |
| 倒计时断连 | 任一路失去就绪状态 | 回到 `preparing`，不开始有效计时 | 显示具体设备原因 |
| `pause` | 会话运行中 | 动力归零，冻结有效训练时间和连续奖励 | 写暂停事件 |
| `resume` | 会话暂停，所有指定玩家重新就绪 | 重新倒计时后运行，连续奖励从零开始 | 条件不足时保持暂停 |
| 单路失联 | 会话运行中 | 该路动力归零；另一条继续 | 记录该路异常 |
| 双路失联 | 体验/正式模式分别按配置处理 | 体验模式继续计时；正式模式 `aborted` | 写明模式和原因 |
| `emergency` | 任意非终态 | 动力归零并锁定急停 | 旧回调全部无效 |
| `reset` | 已急停锁定且人工确认 | 清除安全锁但保持待机，必须创建新会话 | 未确认或故障锁定时拒绝 |
| 记录故障/看门狗超时 | 任意运行状态 | `fault_locked`、动力归零、标记记录不完整 | 页面显示具体存储或控制故障 |
| `end` | 任意非终态 | 记录结束原因、最终统计和零动力 | 只有完整提交后才显示“已保存” |

每条转换会写入事件时间、相对单调时间、旧状态、新状态和原因。意图在队列入队时绑定会话 ID；后台只接受当前 ID，旧页面回调不能作用于新会话。

## 三个时间尺度和样本口径

- 设备采样时间来自头环的序号或更新时间；无法证明快照变化时，样本标为 `unverified_identity`，重复读取不刷新有效期。
- 控制线程每 `control_interval_ms` 调度，默认 50 ms；动力看门狗独立运行，默认 20 ms。
- 页面约 100 ms 读取不可变快照，只用于绘制。

只有序号或更新时间严格递增的设备帧才是新样本。重复帧、乱序帧和插值点不会增加样本数，也不会延长数据新鲜度。原始 Attention 与 EMA 平滑值分开保存；`0` 是否有效由 `zero_is_valid` 冻结在本场配置中。每个样本最多覆盖到 `data_timeout` 结束，暂停期间不累计有效时长。

达标比例为“有效且达标的时间 / 有效时间”。不足两个有效样本时，平均值和趋势为 `暂无足够数据`。竞速位置和胜负是后台根据虚拟动力积分得到的虚拟成绩，报告同时保留传感器实测样本；两路样本按各自时间排序，导出不会把第 N 行当作同一时刻。

## 存储、恢复和回放

`backend/storage.py` 用独立线程批量写入 SQLite，开启 WAL、外键和 `synchronous=FULL`。表包括玩家、会话、参与者、配置快照、逐条 journal、逐路样本、事件、统计和报告状态。控制线程只把有界批次放入队列；磁盘写入或报告导出不会阻塞控制周期。

正常批次默认每 250 ms 提交一次，队列和 `storage_max_lag_seconds` 控制可见积压；超过上限会锁定记录并显示不完整。按默认值估算，进程突然退出时允许丢失的未提交窗口为一个控制周期加一次批次间隔和存储积压上限，约 2.3 秒；结束操作会强制提交，正常运行时通常小于 0.5 秒。SQLite 的 `FULL` 同步模式是持久性策略，断电后的实际恢复时间和树莓派写入负载仍需现场压测，参考 [SQLite PRAGMA synchronous](https://sqlite.org/pragma.html#pragma_synchronous)。启动时会把未完成会话标记为 `process_restart`，并禁止自动恢复动力；数据库启动快照保留最近五份，日志按 2 MiB 轮换五份，磁盘低于阈值会告警。

`python app.py replay --mode simulation --database data/focus.sqlite3 --session-id <id>` 只读地重放 journal 中的时间、帧和意图，并逐个检查点比对生产状态机；缺少检查点、序号缺口、算法版本不符或被篡改都会失败。导出 JSON/CSV 只允许完整报告，保存失败不会显示完整。

报告表已预留 `ai_json` 和版本字段，但本阶段只生成基础统计和原始记录，AI 内容保持空值并由报告状态明确表示，避免把未生成内容误标为完成。

## 验收范围

自动测试覆盖固定回放场景、单双路断连、重复/乱序/过期帧、暂停恢复、急停迟到回调、时间积分、竞速胜负、旧会话隔离、SQLite 写入故障、数据库占用、看门狗锁定和不重复终态写入。当前开发机为 CPython 3.9.13 Windows；`attention_usb`、`RPi.GPIO` 和真实树莓派尚未安装，必须在目标 Pi 上补做低动力空载、单路断连、急停、退出、磁盘满和断电恢复测试。
